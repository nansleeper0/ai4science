# AGENTS.md — обработка измерений pV

Инструкции для агента, выполняющего обработку данных этого учебного проекта.

## 0. Цель и образ результата

По data/measurements.csv вычислить pV каждой строки, отметить подозрительные
измерения и получить статистику остальных наблюдений.

Создать:
- src/build_pv.py — обработчик, запускаемый python3 src/build_pv.py;
- results/pv.csv — столбцы row,pv_kpa_l,suspicious, одна строка на исходное
  измерение, в исходном порядке. row начинается с 1; suspicious — 0 или 1;
- results/pv_summary.json — поля n_total, n_suspicious, mean_pv_clean,
  std_pv_clean, relative_std_clean_percent.

Правила расчёта:
- pv_kpa_l = volume_l * pressure_kpa;
- подозрительная строка: abs(pV / median(pV) - 1) > 0.10;
- медиана вычисляется по всем исходным строкам;
- статистика clean вычисляется по строкам, не отмеченным подозрительными;
- std_pv_clean — выборочное стандартное отклонение, делитель n_clean - 1;
- relative_std_clean_percent = 100 * std_pv_clean / mean_pv_clean.

Причину подозрительного измерения по одной таблице не устанавливать.
Исходные единицы не исправлять без подтверждённого источника.
Числа вычислять из CSV, не записывать готовые ответы константами.

## 1. Критерий готовности

Команда проверки: python3 checks/check.py

Работа завершена, когда команда возвращает код 0, выходные файлы существуют,
исходные данные и независимая проверка не изменены.
Если checks/check.py отсутствует, остановиться и сообщить об этом.
Не создавать и не изменять независимую проверку самостоятельно.

## 2. Карта проекта и источники

data/measurements.csv: volume_l — литры, pressure_kpa — кПа,
temperature_k — К. Старый src/analyze.py и results/analysis.txt относятся
к первой практике, сохраняются как история. Новый обработчик — build_pv.py.
diary.md содержит журнал действий, предыдущие записи сохраняются.

## 3. Инструменты и границы

Python 3 и стандартная библиотека: csv, json, statistics, pathlib.
Сеть, Lean и установка пакетов для этой задачи не требуются.

## 4. Запреты

1. Не изменять data/. [среда] Перед рабочим запуском пользователь закрывает
   каталог от обычной записи командой chmod -R a-w data.
2. Не изменять checks/. [среда] Перед рабочим запуском пользователь закрывает
   каталог от обычной записи командой chmod -R a-w checks.
3. Не читать исходный код и эталоны checks/. [окно] Разрешено запускать
   python3 checks/check.py и читать его диагностический вывод.
4. Выполнять инструменты с подтверждением пользователя. [вызов]
   Пользователь запускает агента с --mode approve.
5. Не удалять и не перезаписывать прежние результаты и записи журнала.
   [окно] Новые расчёты записывать только в указанные новые файлы.
6. Не выполнять git commit, git push и публикацию. [окно]

## 5. Протокол работы

Режим — короткий цикл действия и проверки: прочитать данные, создать
build_pv.py, запустить его, выполнить checks/check.py, прочитать диагностику.
При провале исправлять обработчик, сохраняя постановку и проверку.
Перед окончательным ответом самостоятельно выполнить команду проверки.

## 6. Память

Добавить в конец diary.md короткую запись: что создано, команда и вердикт
проверки. Разделять действия агента и проверку человека. Не заявлять,
что пользователь лично проверил результат или принял его.

## 7. Остановка и бюджет

Не больше 10 вызовов инструментов на эпизод. После двух неудачных проверок
подряд по одной причине остановиться и описать проблему.
При исчерпании бюджета сообщить, что сделано и что осталось; не менять
критерий готовности и не ослаблять ограничения ради успешного ответа.
