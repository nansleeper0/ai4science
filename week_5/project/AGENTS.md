# AGENTS.md — обзор переменности рентгеновских пульсаров

## 0. Цель и образ результата

Проект недели 4 готовит аналитический обзор связи периодической и апериодической
переменности. Сравнение двух моделей (LS1997 shot-noise и M2024 column-eclipse)
завершено и принято. Текущий этап (неделя 5) — литературный граф: записать пять
разных источников по связи периодической и апериодической переменности
аккрецирующих рентгеновских пульсаров, обогатить существующие источники через
OpenAlex, добавить Wikidata-контекст. Новые наблюдения и численные эксперименты
сейчас не выполняются.

Результат первой сессии:
- results/model_comparison.csv — ровно две модели, поля model_id,source_id,mechanism,
  assumptions,prediction,applicability,limitation,pdf_pages;
- results/source_quotes.csv — минимум одна содержательная цитата на каждую модель,
  поля model_id,source_id,pdf_page,claim,quote,role. role: предпосылка/предсказание/результат;
- notes/ и tasks/ — не менее десяти реальных объектов с типами, связями и итогами;
- diary.md — техническая запись, STATUS.md — актуальное состояние.

Результат текущего этапа (неделя 5):
- пять разных источников в notes/ с openalex_id и связью найденЗапросом;
- results/week5_openalex.json и results/week5_wikidata.json с ответами и provenance;
- заметки ЗапросКГрафу для OpenAlex и Wikidata;
- Wikidata-контекст в заметке анализа.

Связный отчёт в reports/ — отдельная задача второй сессии после человеческой приёмки.

### Чего агент не может знать сам

- [W3-ROUND] В кратком отчёте по учебному pV среднее округлять до двух знаков; машинные CSV/JSON не округлять.
- [W3-DECIMAL] В русском тексте десятичный разделитель — запятая; в CSV/JSON — точка.
- [W3-REPORT] Отчёт писать связными абзацами с конкретными результатами и ограничениями; команды оставлять в методике и журнале.
- У LS1997 год журнальной публикации 1997, версия препринта 1996; это не две разные статьи.
- Объект M2024 — V 0332+53; выводы не переносить автоматически на EXO2030+375.
- Совпадение цитаты с PDF подтверждает текст, но само по себе не подтверждает научную интерпретацию.

### Хранилище и классы

Корень проекта — vault. .obsidian/app.json и graph.json настроены; сохранять
имеющиеся настройки. Заметки классов ontology/<Класс>.md построены по YAML;
при необходимости обновить командой python3 src/make_class_notes.py.
Классы не являются конкретными статьями, моделями или задачами.

### Объекты и связи

Каждый объект notes/<уникальное название>.md имеет YAML-frontmatter type: <Класс>,
название конкретного объекта, краткое описание и раздел ## Связи:
- тип: [[<Класс>]]
- <отношение из ontology.yaml>: [[<имя другого объекта или путь к файлу>]]

Отношения ставить в объявленном направлении и между подходящими типами. Имена
заметок уникальны во всём проекте; не включать /, \, :, #, |, [, ]. Ссылки в
разделе Связи не оборачивать в обратные кавычки. Каждый Источник связан хранитсяВ
со своим library/<ID>.pdf. Модель основанаНа Источник. Утверждение относитсяК
Модель и сформулированоВ Источник; у него обязательное поле роль.
Ограничение ограничивает Модель. У Проверки обязательно поле способ:
совпадение цитаты / структура графа / человеческая сверка. Последний вариант
разрешён только после фактического сообщения пользователя.

Файлы являются узлами сами: не создавать notes/Файл.... Для источника нужен один
объект, а не отдельные объекты для PDF и его TXT. Отчёт — сам reports/<имя>.md
с type: Отчёт; он ссылаетсяНа источники и описывает модели/утверждения/анализ.

### Задачи

Поручение записать в tasks/<действие>.md до содержательной работы:
---
type: Задача
status: открыта
---
# <название>
Запрос пользователя: «<дословный запрос>»
Готово, когда: <конкретные файлы, содержимое и команда проверки>
Не входит: <границы>
## Связи
- тип: [[Задача]]

При необходимости выделить 2–3 подзадачи с теми же полями, без повторения
пользовательского запроса; связь подзадачаОт идёт к родителю. Показать план,
затем вести статусы открыта → в работе → выполнена/заблокирована.
У каждой выполненной/заблокированной задачи есть ## Итог с фактическими
действиями и проверкой. Завершённую подзадачу закрывает Анализ, Проверка или
Подготовка через решает, отчёт через выполняет. Родителя могут закрывать
выполненные подзадачи. Критерии после начала не менять.
Принята — только после слов пользователя с записью «Принято пользователем: ...».
Принятые задачи не открывать ради новой работы: создать новую задачу.

### 2.6. Литература и внешние графы

Инструменты расширения `research`: `openalex_search`, `openalex_work`, `openalex_links`
(научные работы и цитирования в OpenAlex), `wikidata_search`, `wikidata_sparql`
(сущности и связи Wikidata). Запросы к OpenAlex — на английском.

Запрос. Каждое обращение к внешнему графу, результат которого попадает в проект, —
заметка `notes/Запрос <дата> <кратко>.md`:

```
---
type: ЗапросКГрафу
source: OpenAlex
retrieved: <дата из поля provenance>
---
# Запрос <дата> <кратко>

Инструмент и аргументы: <имя инструмента и значения аргументов; для SPARQL — текст запроса>
Найдено: <число из ответа>; отобрано в проект: <число> — <по какому условию>

## Связи
- тип: [[ЗапросКГрафу]]
- решает: [[<подзадача>]]
```

Источник. Найденная работа — заметка `notes/<Фамилия год>.md`; при совпадении названий —
`<Фамилия год б>`:

```
---
type: Источник
openalex_id: <W… из ответа>
doi: <из ответа; нет — поле не пишется>
year: <год>
cited_by: <число цитирований из ответа>
oa_status: <значение из ответа>
---
# <Фамилия год>

[источник] <авторы, название, журнал, том, выпуск, страницы, год — как в ответе инструмента>
[источник] Аннотация: <1–3 предложения из поля abstract; нет поля — «аннотации в OpenAlex нет»>
[порождено] Зачем проекту: <одна строка>

## Связи
- тип: [[Источник]]
- найденЗапросом: [[Запрос <дата> <кратко>]]
- написан: [[<имя автора, как в ответе инструмента>]]
- цитирует: [[<другой источник проекта>]]
- хранитсяВ: [[library/<файл>]]
```

Правила:
- Выходные данные переносятся из ответа инструмента без изменений. Чего в ответе нет, в
  заметке нет. Расхождение ответа с файлом в `library/` записывается строкой
  «Расхождение: …» и сообщается пользователю.
- Пометки в заметках и отчётах: `[источник]` — перенесено из ответа инструмента или из
  файла `library/`; `[порождено]` — написано агентом; `[написано]` — слова пользователя.
- Автор — заметка `notes/<имя автора, как в ответе инструмента>.md` с типом `Автор` и
  полем `openalex_id` автора в начале файла. Заметка создаётся только вместе со связью
  `написан` в заметке источника: для первых трёх авторов работы. Один человек — одна
  заметка.
- Связь `цитирует` — только между источниками, которые есть в проекте, и только если её
  подтверждает `openalex_links` или список литературы в файле `library/`.
- Источник, который уже есть в проекте, не дублируется: в его заметку дописываются поля
  из ответа и связь `найденЗапросом`.
- Если одной работе отвечают несколько записей OpenAlex, запиши идентификаторы всех в
  тексте заметки, в поле `openalex_id` — запись с большим числом цитирований; сообщи
  пользователю.
- Открытая версия: если `oa_url` не пуст, скачай файл инструментом `pdf_download` в
  `library/` и свяжи отношением `хранитсяВ`. Если по адресу пришла страница, а не PDF,
  файл не сохраняется: в заметке источника остаётся строка «Открытая версия: <oa_url>».
  Нет открытой версии или файла — задача этим не блокируется, в итоге перечисляются
  работы без локальной копии. На неделе 5 новые PDF не скачиваются: достаточно метаданных.
- Сущность Wikidata записывается в заметке объекта, к которому относится: строка
  «[источник] Wikidata: <Q…> — <подпись>; <свойство>: <Q…> — <подпись>» и связь
  `найденЗапросом` не нужна; запрос записывается заметкой `ЗапросКГрафу`, в тексте
  которой перечислены заметки, куда внесены сведения.
- Параметры отбора (годы, тип, сортировка, число записей) берутся из задачи и
  записываются в заметке запроса.

## 3. Инструменты и источники

Python 3, стандартная библиотека, уже установленные PyYAML и pypdf. Сеть и
установка пакетов не нужны. Работать из корня проекта. Полные тексты локальны
и исключены из Git; каталог хранит версии и SHA-256. При восстановлении копии:
python3 src/prepare_sources.py. На текущей машине источники уже подготовлены.
TXT имеет метки [с. N] по PDF. Формулы и рисунки сверять по PDF. При обрезанном
выводе читать нужные страницы частями; полноту чтения не предполагать.
Для первого сравнения достаточно аннотации, постановки модели, выводов и
страниц с выбранными утверждениями; не заявлять полного прочтения, если его не было.
Небольшие однотипные заметки можно создавать одной командой Python.
